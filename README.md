# Download Speed Tester

Небольшой CLI-скрипт на TypeScript для проверки скорости загрузки по HTTP и HTTPS.
Он выполняет запросы последовательно, показывает текущую среднюю скорость,
выводит результат каждого запроса и общую сводку. Загруженные данные читаются
потоком и не сохраняются на диск.

## Требования

- Node.js 26.x.
- npm, входящий в поставку Node.js.

TypeScript запускается средствами Node.js; отдельная сборка не нужна.
Зависимости проекта нужны для проверки типов, а тесты используют встроенный
модуль `node:test`.

## Установка и запуск

```sh
git clone https://github.com/spacepolice10/download-speed-tester.git
cd download-speed-tester
npm ci

# Десять последовательных загрузок тестового MP4
npm start -- "https://samplelib.com/mp4/sample-30s.mp4"
```

Если используете mise, версия Node.js уже указана в `mise.toml`:

```sh
mise trust
mise install
mise exec -- npm ci
mise exec -- npm start -- "https://samplelib.com/mp4/sample-30s.mp4"
```

Синтаксис команды:

```sh
npm start -- "<address>" [requestNumber]
# Или напрямую:
node index.ts "<address>" [requestNumber]
```

| Аргумент | Описание | По умолчанию |
| --- | --- | --- |
| `address` | Полный URL с протоколом HTTP или HTTPS | Обязательный аргумент |
| `requestNumber` | Количество запросов: целое положительное число | `10` |

Заключайте URL в кавычки: символ `&` иначе может интерпретироваться оболочкой.
Некорректный URL или количество запросов завершают выполнение до загрузки.

```sh
npm start -- --help
```

## Что выводится

Во время загрузки одна строка обновляется не чаще одного раза в 100 мс:

```text
Downloading 1/3… 850.25 KiB/s
```

После завершения строка заменяется полной записью запроса:

| Поле | Значение |
| --- | --- |
| `request` | Номер запроса, начиная с 1 |
| `isDownloading` | `false` в итоговом результате; `true` в обновлениях прогресса |
| `startedAt` | Время начала в формате ISO 8601, UTC |
| `status` | HTTP-статус; `null`, если ответ не был получен |
| `sizeBytes` | Количество прочитанных байтов тела ответа |
| `durationMs` | Полная длительность запроса в миллисекундах |
| `speedBytesPerSecond` | Средняя скорость запроса в байтах/с; `null`, если ответ не получен |
| `medianSpeedBytesPerSecond` | Медиана скоростей отдельных полученных чанков; `null`, если подходящих замеров нет |
| `error` | Описание ошибки, если запрос завершился неудачно |

Средняя скорость — это размер прочитанных данных, разделённый на полную
длительность запроса, включая ожидание ответа. Медиана рассчитывается отдельно
для каждого запроса, а не по всем запросам. Размеры и интервалы чанков зависят
от буферизации, поэтому медиана может заметно колебаться. Показатели относятся
к прочитанному телу ответа, без HTTP-заголовков и накладных расходов сети.

Если загрузка оборвалась, результат сохраняет уже прочитанные байты и частичные
измерения. HTTP-статус `200` сам по себе не означает, что тело было загружено
полностью: в этом случае также смотрите на `error`.

В конце выводится `Summary`: число запросов, успешных и неудачных попыток,
общий объём данных, сумма длительностей запросов, среднее время запроса
и общая средняя скорость. Поле `averageDurationMs` — сумма длительностей,
разделённая на количество запросов, в миллисекундах.
В суммарные байты, время и расчёт среднего времени входят также неудачные попытки.

Скорость в строке прогресса указана в KiB/s: 1 KiB = 1024 байта.
Поля `speedBytesPerSecond`, `medianSpeedBytesPerSecond` и
`averageSpeedBytesPerSecond` в результатах и сводке указаны в байтах/с.

При перенаправлении вывода в файл или pipe промежуточные обновления строки
отключаются: остаются уведомление о начале, результаты запросов и сводка.

## Ошибки и настройки

- Только HTTP-ответы `2xx` считаются успешными.
- После ошибки следующий запрос всё равно выполняется.
- Код завершения `0` означает успешный запуск; `1` — ошибку аргументов или хотя бы одного запроса.
- Тайм-аут каждого запроса, включая чтение тела: 30 секунд (`REQUEST_TIMEOUT_MS`).
- Интервал обновления терминала: 100 мс (`PROGRESS_INTERVAL_MS`).

Обе константы находятся в начале `index.ts`. Ограничение частоты вывода
не пропускает чанки при подсчёте байтов и измерении скорости.

## Проверки и тесты

```sh
npm test                 # Автоматические тесты без внешних запросов
npm run typecheck        # Проверка типов приложения и тестов
npm run check            # Проверка типов и все тесты
npm run test:watch       # Повторный запуск тестов при изменении файлов
```

Тесты используют управляемые ответы `fetch`, потоки и виртуальные часы.
Проверяются последовательность запросов, средняя и медианная скорости,
пустые ответы, HTTP-ошибки, сетевые сбои, обрыв тела ответа, тайм-ауты,
валидация URL и аргументов, справка, вывод в терминал и pipe, ограничение
частоты прогресса, сводки и независимость повторных запусков.
Тайм-ауты моделируются без ожидания 30 секунд.

Для ручной проверки на исходной ссылке изображения:

```sh
npm run test:download       # 10 реальных запросов
npm run test:download -- 3  # 3 реальных запроса
```

Ручная проверка зависит от доступности сети и удалённого сервера.

## Структура проекта

- `index.ts` — запуск, загрузка, расчёты, вывод и справка.
- `types.ts` — общая структура данных запроса `RequestData`.
- `tests/app.test.ts` — автоматические тесты.

При импорте `index.ts` загрузки не запускаются. `await main(args)` возвращает
массив результатов конкретного запуска. `downloadRequest()` позволяет получить
результат отдельного запроса и принимать обновления через `onProgress`;
обновления имеют тип `Partial<RequestData>`.
